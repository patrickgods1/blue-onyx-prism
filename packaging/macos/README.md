# macOS installer package

Unsigned arm64 `.pkg` that installs the same layout as `scripts/install_launchd.sh`:

- program: `/usr/local/blue-onyx-prism` (binaries, licenses, `scripts/uninstall_launchd.sh`, `scripts/launchd_common.sh`, the by-hand training scripts)
- menu bar app: `/Applications/Blue Onyx Prism.app` (the `blue-onyx-prism-tray` binary, `Info.plist` generated by
  `build-pkg.sh`, `LSUIElement` so no Dock icon, ad-hoc signed, bundle id `com.blueonyx.prism.tray`, not relocatable)
  started at login by `/Library/LaunchAgents/com.blueonyx.prism.tray.plist` (`deploy/`; `KeepAlive` false so
  *Quit Tray* sticks; Aqua sessions only). The postinstall also starts it for the logged-in user
  (`bop_tray_start` in `scripts/launchd_common.sh`); the preinstall stops it before an upgrade
- uninstaller: `/Applications/Uninstall Blue Onyx Prism.app` (compiled from `uninstaller.applescript` with
  `osacompile`, ad-hoc signed, bundle id `com.blueonyx.prism.uninstaller`, not relocatable)
- data: `/usr/local/var/blue-onyx-prism` (config, models, cache, downloads, dataset, reviewed labels, training runs), owned by the role account `_blueonyx`
- logs: `/var/log/blue-onyx-prism` (rotated through `/etc/newsyslog.d/blue-onyx-prism.conf`)
- daemon: `/Library/LaunchDaemons/com.blueonyx.prism.plist`

Runtimes are not bundled. The service downloads OpenVINO / ONNX Runtime and the default model on
first start into `download_dir`. The seeded config sets `download_dir`, `cache_dir` and `log_path`
only; an existing config is never overwritten, so an upgrade keeps settings and models.

## Build (on macOS)

```sh
packaging/macos/build-pkg.sh <version> <bin-dir> blue-onyx-prism-<version>-macos-aarch64.pkg
```

`<bin-dir>` holds the release `blue-onyx-prism`, `blue-onyx-prism-benchmark` and `blue-onyx-prism-tray`. Uses `pkgbuild`,
`productbuild` and `osacompile`; the postinstall helpers come from `scripts/launchd_common.sh`.

Test on a macOS machine with sudo: `packaging/macos/smoke-test.sh <pkg>` (installs, waits for
`/v1/status`, checks the uninstaller and menu bar apps and the LaunchAgent, uninstalls keeping the data, reinstalls over it
with the account's id changed, then purges). A kept data root or log dir holding anything (the folder
or a file deep inside) of another owner or group is chowned as a whole (`bop_own_kept_dirs`).
`packaging/upgrade-test.sh` (packaging.yml) installs the latest published pkg, seeds a config edit, a
root-owned label file, a frame and a training `runs.json`, upgrades to the new pkg and checks the
daemon, one detection and that all of it is unchanged.

## Install an unsigned package

Gatekeeper blocks a package that is not signed or notarized. Double-click it, dismiss the warning,
then open System Settings > Privacy & Security, scroll to the message about the blocked package and
click "Open Anyway". Or from Terminal: `sudo installer -pkg <file>.pkg -target /`.

After install open https://localhost:32169/ (status and configuration; the browser warns once
about the self-signed certificate: compare its SHA-256 fingerprint with
`sudo -u _blueonyx /usr/local/blue-onyx-prism/blue-onyx-prism --config /usr/local/var/blue-onyx-prism/blue_onyx_prism_config.json tls-fingerprint`).
Blue Iris uses http://<this Mac>:32168/.

## Uninstall

Open *Uninstall Blue Onyx Prism* in Applications, choose *Keep My Data* (the default button) or
*Delete Everything*, and enter an administrator password. The app only runs the script below as
root; from Terminal:

```sh
sudo /usr/local/blue-onyx-prism/scripts/uninstall_launchd.sh            # keep data, logs, account
sudo /usr/local/blue-onyx-prism/scripts/uninstall_launchd.sh --purge    # also delete them
```

The data root holds the config, models and, unless they were pointed elsewhere, the dataset, reviewed
labels and training runs, which no download brings back. A reinstall picks it up, and the postinstall
hands the data root and the log dir to `_blueonyx` when the account's id changed. Keeping the data
also removes the script itself, so it prints what deletes them later:

```sh
sudo rm -rf /usr/local/var/blue-onyx-prism /var/log/blue-onyx-prism; sudo dscl . -delete /Users/_blueonyx; sudo dscl . -delete /Groups/_blueonyx
```

The script stops the daemon and removes its plist, the newsyslog entry, the installer receipt
(`pkgutil --forget com.blueonyx.prism`), the menu bar app and its LaunchAgent, the program dir and the uninstaller app.

macOS lets only some apps change user accounts, even as root: from the uninstaller app,
deleting `_blueonyx` fails with `eDSPermissionError` while it works from Terminal. The script
then removes everything else, prints the commands and exits 4, and the app offers *Remove in
Terminal* (it opens a `.command` file that runs
`sudo dscl . -delete /Users/_blueonyx; sudo dscl . -delete /Groups/_blueonyx`). The account is
harmless if left; a reinstall reuses it.
